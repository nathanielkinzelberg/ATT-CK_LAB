## What T1057 Collects

| Field | Source | Notes |
|---|---|---|
| pid | /proc directory listing | each numbered folder is a process |
| name | /proc/{pid}/comm | the process name as a single line |
| uid | /proc/{pid}/status | the real UID of the process owner |
| process_count | calculated | total number of processes found |

---

## Key Concepts Learned

### Process
A running instance of a program. Every process has a unique PID assigned by the OS. The OS uses the PID to track and manage it.

### /proc/{pid}/
Every running process has its own folder inside /proc named after its PID. Inside that folder are files exposing live information about that process — name, owner, memory usage, open files, and more.

### /proc/{pid}/comm
A file containing just the process name. One line, no extra information.

### /proc/{pid}/status
A file with detailed process information. We read it line by line and look for the Uid line which tells us who owns the process.

### UID (User ID)
A number that identifies a user on a Linux system. Root is always UID 0. Regular users have UIDs starting from 1000. Knowing the UID of a process tells an attacker whether it's running as root or as a regular user.

### Sorting with lambda
`sorted(processes, key=lambda p: p["pid"])` sorts the list by PID. A lambda is a small anonymous function written inline — `lambda p: p["pid"]` means "for each process p, sort by its pid field."
